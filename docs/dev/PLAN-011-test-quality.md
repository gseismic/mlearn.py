# PLAN-011：补齐测试断言与稳定执行方式

## 问题

现有测试大量只打印结果，没有断言，错误算法也会显示通过。测试还通过多个 `config.py`
使用相对当前工作目录修改 `sys.path`，从不同入口运行 pytest 时可能无法导入 `mlearn`。

## 目标

1. 每个测试函数至少验证一个明确行为。
2. 测试失败能够反映数值、形状或状态回归。
3. 测试导入不依赖当前工作目录。
4. 项目根目录提供统一 pytest 配置。
5. 删除测试中的手工 `sys.path` 修改。

## 实施步骤

1. 为所有仅打印的测试增加数值、形状或精度断言。
2. 删除测试文件中的 `import config`。
3. 删除所有测试目录下的 `config.py`。
4. 新增 `pytest.ini`，固定 `testpaths` 和项目根 `pythonpath`。
5. 检查每个 `test_` 函数都包含有效断言或异常断言。

## 验证

1. 静态检查不存在 `import config` 和测试路径注入。
2. 静态检查每个测试函数至少包含断言。
3. 运行 `python -m pytest -q`。
4. 记录普通 `pytest -q` 的剩余环境问题，并在后续可选依赖计划中处理。

## Review 检查点

1. 断言阈值是否稳定且能捕获真实退化。
2. 是否仍有仅打印结果的测试。
3. pytest 配置是否只影响本项目测试。
